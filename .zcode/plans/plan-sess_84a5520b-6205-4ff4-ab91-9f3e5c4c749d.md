# Multi-restaurants : Saint-Mard + Persan, un seul site (PWA)

## Vue d'ensemble
Un seul site, une seule carte (menu global), **deux restaurants** :
- **Saint-Mard** — Av. de la Font du Berger, 77230 Saint-Mard — ☎ 07 51 50 39 00 (source : restaurants-de-france.fr ; horaires non publiés → défaut = ceux de Persan, éditables dans l'admin)
- **Persan** — Av. Jacques Vogt, 95340 Persan — ☎ 07.51.56.59.51 — 7j/7 11h–14h / 18h–22h30

Firebase n'est pas encore configuré → tout tourne en **mode démo** (localStorage), et le code est prêt à basculer automatiquement sur Firestore dès la configuration (même mécanisme que le menu actuel).

## 1. Modèle de données (`lib/data.ts`)
- Type `Location` : `{ id, name, address, postal, city, phone, hours, deliveryFee, minDelivery, open, deliveryZones: string[] }` (zones = codes postaux livrés).
- `LOCATIONS: Location[]` par défaut : Saint-Mard (zones 77 : 77230, 77410, 77270…) et Persan (zones 95 : 95340, 95420, 95150…). Menu/produits/promos/banner restent globaux.
- `Order` : ajout `locationId`.

## 2. Réglages par restaurant — prêts Firestore + démo
- Nouveau doc `locations/settings` (`{ items }`) avec abonnement `onSnapshot` (comme `MENU_DOC`) et route admin `/api/admin/locations` ; tant que Firebase n'est pas configuré : localStorage `mc_locations`, synchronisé entre onglets.

## 3. Sélecteur d'entrée (`lib/location-store.tsx` + `components/LocationGate.tsx`)
- `LocationProvider` dans `app/layout.tsx` ; choix mémorisé (localStorage `mc_location`).
- Popup plein écran « Choisissez votre restaurant » au 1er accès :
  - **À emporter / sur place** : deux cartes Saint-Mard / Persan → choix direct.
  - **Livraison** : champ code postal → si le CP est couvert, assignation automatique du resto le plus proche (« Livré par My Chicken Persan ») ; sinon message de zone non livrée.
- Badge du restaurant sélectionné dans la **Navbar**, modifiable à tout moment.

## 4. Checkout (`components/CartSection.tsx`)
- Frais de livraison / minimum de commande / ouvert-fermé lus depuis le restaurant sélectionné (remplace `menu.config.*`).
- `locationId` envoyé à `/api/orders` et `/api/checkout` ; préfixe du numéro de commande selon le resto (`SM-…` / `PS-…`).
- En livraison, le CP saisi doit appartenir aux zones du resto assigné.

## 5. Commandes
- Même collection `orders` avec champ `locationId` (aucune migration cassante) ; `useOrders()` filtre par restaurant actif.

## 6. Admin unique avec bascule (`components/admin/AdminApp.tsx`)
- Sélecteur « Restaurant : Saint-Mard / Persan » en haut du dashboard, persisté.
- **OrdersTab** : commandes du restaurant sélectionné uniquement.
- **SettingsTab / LocationsTab** : édition par restaurant (horaires, frais, minimum, zones CP, ouvert/fermé, tel). Carte et promos restent communes.

## 7. Dé-hardcodage
- `Footer.tsx`, `Contact.tsx` (adresses, téléphones, horaires, zones, iframes Maps), `layout.tsx` (metadata), `CartSection.tsx` : dynamiques selon le restaurant sélectionné ; la page Contact liste les **deux** restaurants avec lien itinéraire.

## 8. PWA (« on ne sort plus de ça »)
- `public/manifest.webmanifest` : display `standalone`, icônes 192/512 générées depuis le logo, start_url `/`.
- Meta tags PWA dans `layout.tsx` + `public/sw.js` (cache des assets, network-first pour API/pages) enregistré côté client.

## 9. Vérification
- `npm run build`, puis test manuel : popup d'entrée, à emporter, CP 95340 → Persan / 77230 → Saint-Mard / CP inconnu → refus, badge Navbar, checkout avec `locationId`, bascule admin, installation PWA.

Sources infos Saint-Mard : [restaurants-de-france.fr](https://restauration-rapide.restaurants-de-france.fr/ville/saint-mard-77), [fiche My Chicken Saint-Mard](https://restaurant.restaurants-de-france.fr/my-chicken-3397880.html).
